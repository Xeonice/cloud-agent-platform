# Close Gate Blind Spots and CI Hygiene

## Why

The 2026-07-28~30 series ("wire-orphaned-test-suites" → "converge-contracts-*") turned written rules into executable gates — but the gates themselves have measured blind spots, and CI carries debts those changes explicitly deferred. Measured on `main` @ `fb43e5a`: the symbol ban in `sandbox-package-boundary.test.mjs` walks only 2 roots (`src/sandbox`, `src/terminal`) while its import ban already walks all of `apps/api/src` — a live simulation of the full-scope ban finds **6 violating files** the gate cannot see today; `provider-contract-parity-check.mjs` hardcodes 3 test dirs (a hand-maintained list of exactly the kind wire-orphaned's design rejected — and a literal `sandbox-provider-*` glob would silently drop `sandbox-cloud-http`); `agent-identity-branch-check.mjs` enumerates 10 scaffolding files instead of scanning the complement; the `packages/sandbox` facade is **19 `export *` lines with zero named exports**, leaking every provider internal through the barrel (registered as P7 "no mechanism"). Meanwhile ci.yml states on adjacent lines that boot-smoke both IS and IS NOT a required check, `coverage:sandbox` has zero consumers, `test:visual` and terminal-stories are complete harnesses wired into no workflow, `turbo.json` references a `tsconfig.base.json` that does not exist (a twice-deferred, twice-recorded debt), and the quarantine list holds 3 entries whose owning change never started. Every blind spot is a place where the promises already written into specs — provider parity for third-party packages, no agent-identity branches, boot survival of in-flight tasks — are unenforceable.

Entries are `{count, samples[], change}` with per-entry reason/ownership, count-based so they survive unrelated refactors. The comparator is a small shared module — R7/R11/S2 ratchets in later phases reuse it.

## Capabilities

### New Capabilities

- `ratchet-baselines`: shrink-only tolerated-violation baselines for gates with known 存量 — strict fail-closed comparison (new violation red, stale entry red, shrink committed same-PR, zero deletes the baseline), count+samples entry format with per-entry ownership, one shared comparator consumed by every ratcheting gate, each baseline paired with a self-test proving it can go red.

### Modified Capabilities

- `sandbox-provider-port`: the provider-center facade's public surface becomes an explicit reviewed whitelist — `export *` leaking of provider internals is a violation, tolerated symbols are enumerated with phase-7a ownership; parity-check participation is discovered from package capability (recursive, zero-match fails), never a hand-maintained directory list, so a new provider package enters parity with no registration.
- `agent-runtime`: the no-agent-identity-branch requirement is enforced by complement scan — everything is scanned except an explicit exemption list (the 2 runtime implementations), instead of an enumerated 10-file scaffolding allowlist; an empty scan is a failure, new hits require a fix or a three-field exemption.
- `monorepo-foundation`: the CI boot-smoke requirement gains a stateful variant — boot with a pre-seeded in-flight running task and assert the restarted process re-adopts it — because liveness of a clean boot provably does not cover the re-adoption path; the symbol-boundary gate's scope extends from 2 roots to the full `apps/api/src` tree with the R3 ratchet carrying the 存量.
- `test-suite-discovery`: a declared suite that runs in no CI lane is a violation of "every package's tests gate merges" — closing the concrete instances (`test:visual`, terminal-stories, `coverage:sandbox` wire-or-delete, `test:cors-headers` named step); visual lanes additionally pin their rendering environment and treat baselines as reviewed source.
