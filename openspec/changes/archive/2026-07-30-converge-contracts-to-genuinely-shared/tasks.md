- [x] 3.1 `SmtpConfigRead`: the api returns `EMPTY_SMTP_CONFIG_READ = { host: '', port: 0, user: '', from: '', … }` while the contract declares `host/user/from` as `.min(1)` and `port` as `.min(1)`. Decide which is right — an unconfigured SMTP setup is a real state, so the question is whether the contract should model it — and record the decision before changing either side. **Decided: the contract models it** (design D6, written before the edit). Three unset states are reachable, not one — the controller's blank tuple, a row saved without a password (full tuple, `hasPassword: false`, so that flag is not a discriminant), and the console mock's fixed Resend host/port/user with an empty `from`. The third rules out the tidier two-branch `z.literal('')` union, which would have rejected a shape the console renders. So the read relaxes `host`/`user`/`from` to `z.string()` and `port` to `.min(0)`, while `SaveSmtpConfigRequestSchema` keeps every `.min(1)`: a read projects a possibly-unset singleton, a save creates it, and the strictness belongs where it can still reject something.
